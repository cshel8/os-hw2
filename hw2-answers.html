(c) Explain in two or three sentences why a process switch costs much more time than a mode switch. Use the steps in (b).

A process switch takes more time than a mode switch because the operating system must save the current process's context, update its PCB and queue, and select another process to run. It must also update memory-management information and restore the new process's saved context. A mode switch only changes the CPU's execution mode and does not require switching to a different process.

(d) Suppose Program A's parent did not call wait(NULL) and instead kept computing for an hour, while the child ended within a millisecond. What state is the child in during that hour, what does the kernel still keep about it, and why does the kernel keep it?

The child becomes a zombie process because it has finished executing, but its parent has not called wait(NULL) to collect its termination status. The kernel keeps a small process table entry containing information such as the child's process ID and exit status, even though the child is no longer running. This information is retained so the parent can eventually retrieve the child's termination status and allow the kernel to fully remove the process entry.

(c) What is jacketing, and which weakness of user-level threads does it work around?

Jacketing is a technique used by user-level thread libraries to wrap potentially blocking system calls with a nonblocking check. If the operation would block, the library temporarily suspends that thread and runs another thread until the operation can be retried. This works around the weakness of user-level threads where one blocking system call can cause the entire process and all its threads to stop running.

(b) A team measures a speedup of 3.0 on 4 cores for another program. Solve Amdahl's law for f, and keep it as an exact fraction (rounding it can move a borderline answer). Using that f, predict the speedup on 12 cores, and find the smallest number of cores that gives a speedup of at least 5.

1. Parallel fraction (f):

3 = 1 / [(1 − f) + f/4]

1/3 = 1 − 3f/4

3f/4 = 2/3

f = (2/3)(4/3) = 8/9

2. Speedup on 12 cores:

S(12) = 1 / [1/9 + (8/9)/12]

S(12) = 1 / (5/27) = 5.40

3. Minimum cores for speedup ≥ 5:

9N / (N + 8) ≥ 5

9N ≥ 5N + 40

4N ≥ 40

N ≥ 10

Final results: The parallel fraction is 8/9, the predicted speedup on 12 cores is 5.40, and the minimum number of cores needed to achieve a speedup of at least 5 is 10.

(c) Grand Central Dispatch (macOS and iOS) lets programmers get concurrency without creating threads themselves. Explain how: what the programmer writes, where it goes, and who runs it. Why is this cheaper than creating one new thread per task?

Grand Central Dispatch (GCD) allows programmers to achieve concurrency by writing tasks as blocks of code and placing them into dispatch queues. GCD manages a pool of reusable worker threads and assigns queued tasks to available threads, while the operating system schedules those threads onto CPU cores.

This is cheaper than creating a new thread for every task because GCD reuses existing threads, reducing thread creation and destruction overhead, memory usage, and unnecessary context switching. It also adjusts thread usage based on available system resources.
